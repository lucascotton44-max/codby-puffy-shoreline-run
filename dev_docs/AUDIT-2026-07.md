# Shoreline Run — Repository Audit (July 2026)

Phase 1 static repository audit. Documentation only: no gameplay, visual, refactor, dependency, or formatting changes were made in this pass. Everything below is grounded in code inspection, file measurement, and one build run; nothing was runtime-tested in a browser during this audit, and runtime claims are explicitly marked as unverified.

---

## 1. Executive summary

**What is functional (verified statically):** The game is a single-scene Phaser 3.90 prototype with a complete, data-driven five-level campaign (three shoreline/canal traversal levels, one all-fragments canal level, one Lord Malefacto boss arena), plus four direct-URL test slices including the Quake donair boss and Calvin's Creature Room secret tribute level. Desktop keyboard controls, mobile multi-touch controls (hold-to-move, buffered jump, glide-on-hold, switch with cooldown, tap-to-start/restart), character switching, Puffy glide, power-ups (Kelp Shield / Tide Lift / Story Spark / Tiderunner), Scuttleclaw patrol+stomp, both boss state machines, per-level music + ambient beds, the H hitbox debug overlay, the fullscreen button, and the `?level=` direct-route system are all fully wired in code. The build passes cleanly (`tsc` strict + custom dist assembler, exit 0, no warnings). Every one of the 115 referenced asset files exists on disk — there are no dangling asset paths.

**What is fragile:** Almost all runtime behavior lives in one 4,504-line class ([ShorelineScene.ts](../src/scenes/ShorelineScene.ts)) that owns input, physics wiring, HUD, overlays, audio lifecycle, level construction, boss integration, camera/parallax reseating, and the sketchbook gallery. Cross-scene state is carried through eight registry flags plus class fields that survive `scene.restart()` — one field (`isDirectTestLevel`) already demonstrates sticky-state behavior across restarts. The mobile control layer is a hand-rolled pointer-set state machine whose flags are consumed at three different sites in the update loop; it works by careful ordering, and any reordering of `update()` is a regression risk.

**What most threatens a polished public proof of concept:** Asset weight and load presentation. The scene front-loads **163 MB** of assets in a single `preload()` — including **72 MB of uncompressed WAV audio** (one music loop is 20.7 MB) and ~80 MB of backgrounds — with **no loading progress UI** of any kind. On a public connection this is minutes of dark canvas, and on iOS the decoded-PCM memory cost of the WAVs is a real tab-crash risk. This is the single highest-impact fix available and it requires no gameplay code changes.

### Build pipeline (important asymmetry)

- **Dev:** `npm run dev` → Vite serves `index.html` + TS directly. There is **no `vite.config.*`** — all defaults.
- **Prod:** `npm run build` does **not** use Vite. It runs `tsc -p tsconfig.build.json` (NodeNext modules, `outDir: dist/assets`, **`sourceMap: true`**) and then [scripts/build.mjs](../scripts/build.mjs) copies `public/` into `dist/`, copies **unminified** `phaser.esm.js` (7.5 MB) to `dist/vendor/`, writes a default-export shim (`phaser-default.js`), and generates a fresh `dist/index.html` with an import map (`"phaser": "./vendor/phaser-default.js"`). All paths are relative, so the dist deploys to sub-paths.
- Consequence: dev and prod use different module resolution and loading paths. The one known divergence point (`import.meta.env`) is correctly guarded in [main.ts:29-32](../src/main.ts) and [ShorelineScene.ts:2672-2679](../src/scenes/ShorelineScene.ts) (`isQaInvulnerable`), with comments acknowledging the split.

### Scene/flow model

There is exactly **one Phaser scene** (`ShorelineScene`, key `'ShorelineScene'`). All level transitions are `this.scene.restart()` plus registry flags:

| Registry key | Purpose |
|---|---|
| `shorelineCurrentLevelIndex` | Which `LEVELS` index to build. |
| `shorelineStartLevelImmediately` | Skip title overlay (used by `advanceToNextLevel`). |
| `shorelineRestartCurrentLevel` | Keep the stored level on restart (does **not** auto-start — see finding F-04). |
| `shorelineSecretRoute` / `shorelineSecretReturnToMain` | Chalk-door entry into Calvin's Creature Room and the return trip to level 1. |
| `shorelineAudioUnlocked`, `shorelineMusicEnabled`, `shorelineSfxEnabled` | Audio unlock + toggles persisted across restarts. |

Rendering uses a two-camera split created in `create()` ([ShorelineScene.ts:390-400](../src/scenes/ShorelineScene.ts)): `cameras.main` renders `worldLayer` only; a `uiCamera` at fixed zoom renders `uiLayer` (HUD, overlays, touch buttons). A 14 px cinematic matte (`PRESENTATION_MATTE_Y`) frames both. Level 1 additionally runs a locked 1.3× world zoom (`resetCameraState`) with a one-shot `reseatLevelOneParallax()` pass that counter-scales screen-fixed dressing (opt-out via `skipReseat` data flag).

### Completion / restart flows (as coded)

- **Non-boss levels:** reaching `endX - 26` with enough fragments → `endLevel(true)`; with too few → transient "Need N more Tide Relic(s)" message ([checkFallOut](../src/scenes/ShorelineScene.ts) L3364-3385).
- **Win with next level:** ENTER or tap → `advanceToNextLevel()` (auto-starts next level, skipping the title).
- **Win at campaign end (Malefacto):** "DEMO COMPLETE"; R/tap → `restartFromLevelOne()` (falls back to URL/`LEVELS[0]` because no keep-flags are set).
- **Game over:** R/tap → `restartCurrentLevelOrReturnFromSecretRoute()` — same level, but back to the **title overlay**, not directly into play (F-04).
- **Canal → boss:** `shouldPlayBossTransition()` plays the lock-chamber cutscene image + flash + UI-camera fade, then auto-advances.
- **Creature Room completion:** sketchbook gallery over the unified panel; R/tap returns to level 1 when `shorelineSecretReturnToMain` is set.

**F-01 · P1 — 163 MB front-loaded preload with no loading UI**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `preload()` (L277-381); [constants.ts](../src/config/constants.ts) `AUDIO_PATHS`; `public/assets/`.
- Evidence: `preload()` loads every level's backdrop, every parallax tile set, every atlas, and **all 21 audio files** regardless of the current level. Measured on disk: referenced assets total **163.2 MB** — audio 72.4 MB (all `.wav`: the Creature Room theme alone is 20.7 MB; four ambient beds ≈ 5.4 MB each), backgrounds 80.1 MB. `git grep "load.on"` finds no progress handler; there is no loading bar, spinner, or text.
- User-visible consequence: on a typical public connection the player watches a dark 960×540 canvas for the entire download. On iOS, WebAudio `decodeAudioData` expands 16-bit PCM to Float32 (~2× in RAM): ~72 MB of WAV becomes ~145 MB of decoded audio buffers before textures — a realistic Safari tab-eviction risk. This is the main gate between "works on my machine" and a public demo.
- Recommended next action (separate pass, no gameplay changes): (1) transcode music/ambient/SFX to OGG Vorbis or M4A (~90 % smaller; keep WAV originals in `dev_assets/audio_originals/`); (2) add a minimal preload progress bar; (3) afterwards, consider per-level lazy loading of backdrops/parallax. Each is independently shippable.

**F-02 · P2 — Production build ships unminified: 7.5 MB Phaser + sourcemaps, and dev/prod pipelines diverge**
- Files: [scripts/build.mjs](../scripts/build.mjs) L13-24; [tsconfig.build.json](../tsconfig.build.json) (`sourceMap: true`); [package.json](../package.json) `build` script.
- Evidence: the dist build copies `node_modules/phaser/dist/phaser.esm.js` verbatim (7.50 MB measured; the minified `phaser.esm.min.js` sibling is ~1.6 MB) and emits per-file compiled JS + `.js.map` (0.57 MB) with no bundling/minification. Vite exists in devDependencies but `vite build` is never invoked.
- User-visible consequence: ~7 MB of extra JS download and full readable source shipped to a public host. Also a structural risk: dev (Vite, pre-bundled deps) and prod (import map, NodeNext output) resolve modules differently, so prod-only failures are possible and currently only guarded by convention (the two `import.meta.env` guards are correct today).
- Recommended next action: either point the vendor copy at `phaser.esm.min.js` + disable `sourceMap` for public builds (two-line change), or adopt `vite build` as the production pipeline in a dedicated pass. Decide deliberately; do not mix with gameplay work.

**F-03 · P2 — Canal level demands 12/12 fragments (all-perfect gate mid-campaign)**
- Files: [levels.ts:343-344](../src/config/levels.ts) (`totalFragments: 12, requiredFragments: 12`).
- Evidence: every other traversal level is 8/10; this one requires perfection, including fragments on the highest docks (x=1225 y=282, x=2510 y=310), with one Scuttleclaw patrol and three water kill zones. Missing one means backtracking the full 3,450 px world (the "Need N more" message only fires at the end marker).
- User-visible consequence: the harshest difficulty spike in the campaign sits at level 4 of 5; a public-demo player who misses one high fragment gets a confusing full-level walk-back rather than a fail state.
- Recommended next action: design decision, not a bug fix — either relax to 10/12 or treat as intentional and runtime-QA the walk-back experience. Flag for the next level-tuning pass.

**F-04 · P2 — "Try Again" after game over returns to the title overlay, not into play**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `restartCurrentLevelOrReturnFromSecretRoute()` (L682-700), `selectCurrentLevel()` (L635-660), `create()` (L420-427).
- Evidence: the game-over panel says `R / TAP: Try Again`. The restart path sets `shorelineRestartCurrentLevel` (which only preserves the level index); `create()` auto-starts a run only when `shorelineStartLevelImmediately` is set. So the retry lands on the title overlay and needs a second input to actually start.
- User-visible consequence: every death costs an extra tap/keypress and a "why am I on the menu again" beat — most felt on mobile. Playable, mildly misleading copy.
- Recommended next action: one-line candidate fix in a future pass (set `shorelineStartLevelImmediately` in the restart path, or reword the prompt). Needs a product decision on whether the title-return is intentional pacing.

**F-05 · P2 — No mid-run restart affordance on mobile**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `createTouchControls()` (L2462-2598 — buttons: left, right, jump, switch, FS only); `update()` restart handling (L441-448, keyboard `R` only).
- Evidence: the tap-anywhere handler only queues actions when `!isRunStarted` or `isEnded`. During live play there is no touch path to `restartCurrentLevelOrReturnFromSecretRoute()`.
- User-visible consequence: a mobile player who wants to bail (e.g., missed fragments on the 12/12 canal level and doesn't want the walk-back) must deliberately die or finish. Combined with F-03 this is the worst mobile UX interaction in the campaign.
- Recommended next action: small pause/restart touch control in a dedicated mobile-controls pass (protected-system change — needs its own QA round).

**F-06 · P2 — Fullscreen is silently a no-op where unsupported; no keyboard fallback**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `createFullscreenButton()` (L2175-2207).
- Evidence: `target.requestFullscreen?.()` with `p?.catch(() => {})`. iPhone Safari does not implement element `requestFullscreen`; the optional-chain + swallowed rejection means the FS button does nothing there, with no user feedback. There is also no keyboard shortcut (F) on desktop.
- User-visible consequence: iPhone players tap FS and nothing happens.
- Recommended next action: runtime-verify on iOS; then either hide the button when `document.fullscreenEnabled` is false or fall back to a CSS maximize. Trailer capture on desktop is unaffected.

**F-07 · P3 — README.md and CLAUDE.md describe an older game than the code**
- Files: [README.md](../README.md) (L40, L42-48, L67-73), [CLAUDE.md](../CLAUDE.md) "Current Game State".
- Evidence: README claims the in-game controls line is `1 Cod B'y | 2 Puffy | H Debug | M Music | N SFX`; the code renders `1 Cod B'y | 2 Puffy | R Restart` (`getHudSwitchHintText`, [ShorelineScene.ts:3848-3850](../src/scenes/ShorelineScene.ts)). README's "Demo Status" says one playable level and three power-ups; there are five campaign levels, four test slices, and four power-up kinds. **F-08 · P3 — Fall-out death check is unreachable; pit deaths actually work via repeated water damage**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `checkFallOut()` (L3364-3369) vs `createPlayer()` (L1820, `setCollideWorldBounds(true)`); `physics.world.setBounds(0, 0, worldWidth, GAME_HEIGHT)` (L387).
- Evidence: with world-bounds collision on and the world exactly `GAME_HEIGHT` tall, `player.y` can never exceed `GAME_HEIGHT + 80`, so the fall-out branch is dead code. Players landing in gaps stand on the world floor inside a water `HazardZone` and take 1 damage per 900 ms cooldown tick with knockback until dead or escaped.
- User-visible consequence: none today — the water-tick path produces a slower, bouncier pit death than a classic fall-out. Worth knowing before anyone "fixes" pits by tuning the dead branch.
- Recommended next action: none this phase; document only. If pit deaths ever feel wrong in QA, this is why.

**F-09 · P3 — Damage knockback direction ignores hazard geometry**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `damagePlayer()` (L3359-3360).
- Evidence: `direction = player.x > endX/2 ? -1 : 1; setVelocity(direction * -150, -250)` — knockback always pushes toward the nearer level edge, regardless of which side the hazard is on. In the second half of a level the push is rightward, which can shove the player further across a water zone.
- User-visible consequence: occasional "the game pushed me deeper into the hazard" moments; mitigated by the 900 ms damage cooldown. Playable.
- Recommended next action: candidate for a feel pass (knock away from the contacted hazard body instead); requires QA on all five campaign levels afterwards — do not bundle.

**F-10 · P3 — Endpoint-blocked message spawns a timer every frame**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `checkFallOut()` (L3375-3382).
- Evidence: while standing past `endX - 26` without enough fragments, each frame re-sets the message and schedules a fresh 900 ms `delayedCall` (~60 timers/s). Behavior is still correct (the message clears 900 ms after leaving the zone) and `setText` short-circuits on identical text.
- User-visible consequence: none observed statically; minor timer churn.
- Recommended next action: nothing this phase; trivial guard if ever touched.

**F-11 · P3 — Stale timing comment in QuakeBoss**
- Files: [QuakeBoss.ts:31-36](../src/objects/QuakeBoss.ts).
- Evidence: header comment says "recovery 850 = ~3.0s per throw"; the constant is `RECOVERY_MS = 1500` (actual cycle ≈ 3.65 s).

**F-12 · P2 — Quake arena's `endX` (3000) lies outside its world (1320); completion relies on it being unreachable**
- Files: [levels.ts:670-686](../src/config/levels.ts) (`worldWidth: 1320, endX: 3000`); [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `checkFallOut()` L3371 (walk-to-end applies because the level has no `boss` property — Quake uses `quakeBoss`), `update()` L525-527 (`isMatchOver()` → `endLevel(true)`).
- Evidence: with `requiredFragments: 0`, reaching `endX - 26` would instantly win — it's only prevented because world-bounds collision caps x at 1320. The end-marker beacon is also created at x=3000, off-world (harmless, invisible).
- User-visible consequence: none today; the fight ends correctly through the dap flow. The fragility is structural: promoting this definition into a campaign boss level (or widening the arena) without noticing the sentinel `endX` would let players walk past Quake to an instant win.
- Recommended next action: when Quake graduates from `testOnly`, give boss-completion levels an explicit "no walk-to-end" flag instead of an out-of-bounds `endX` sentinel. No change this phase.

**F-13 · P3 — `isDirectTestLevel` is sticky across `scene.restart()` (proof that non-reset fields leak between lives)**
- Files: [ShorelineScene.ts](../src/scenes/ShorelineScene.ts) `selectCurrentLevel()` L644-656 — the stored-level branch never clears the field, and L656 ORs it with its previous value; `resetRunState()` (L2717-2749) does not reset it. `scene.restart()` reuses the same Scene instance, so class fields persist.
- Evidence: start any level via `?level=...`, then advance levels — the flag remains `true` for the rest of the session; completion copy shows the direct-test variants ("Run Again") and final-win R replays the current level instead of restarting the run.
- User-visible consequence: limited today (URL-entry is a dev flow). The pattern is the real finding: any future field not added to `resetRunState()` will leak the same way.
- Recommended next action: when next touching the file, either reset the flag in the keep-stored branch or fold it into `resetRunState()`; adopt "every new stateful field gets a reset line" as review policy.

**F-14 · P3 — Trailer capture mode is a compile-time constant**
- Files: [ShorelineScene.ts:92-93](../src/scenes/ShorelineScene.ts) (`TRAILER_CAPTURE_MODE = false`), consumers at L2138-2141, L2261-2264, L2463.

## 7. Protected-system risk assessment

Ranked by likelihood of accidental regression during future passes:

1. **The touch-input flag machine** (`touchInput`, `touchPointers`, `jumpQueuedUntil`, `switchQueuedUntil`). `jumpJustDown` is consumed at three distinct sites (`update()` L450-460 end-screen tap, `handleTitleInput()` L2282, `handleMovement()` L2867), and correctness depends on `update()`'s exact early-return ordering (story-cards → restart → end-tap → debug → title → gameplay). Any reordering, or a new consumer of the flags, can silently break "tap to start", "jump while moving", or "tap restart". This is the highest-risk protected system.
2. **`scene.restart()` + registry lifecycle.** Five routing flags plus persistent class fields (F-13 shows the failure mode). Any new feature that adds session state must join `resetRunState()` or it will leak across lives/levels.
3. **Level-1 zoom/reseat stack** (`resetCameraState` L2769-2778, `reseatLevelOneParallax` L561-595, `skipReseat` contract in [paintedParallax.ts](../src/scenes/paintedParallax.ts)). Adding any screen-fixed dressing to level 1 without following the scrollFactor/skipReseat rules will visibly mis-seat the painted stack at 1.3×.
4. **Mobile layout detection** (`shouldUseMobileTouchControls`). Single evaluation per scene lifecycle; UA/pointer heuristics. Safe today, brittle against "small change to HUD" passes and untested convertible devices.
5. **Boss completion polling.** Quake's win is polled (`isMatchOver()` in `update()` L525-527) while Malefacto's is event-driven (`takeHit` → `endLevel`). Two idioms for the same outcome invite a future edit that breaks one. Also F-12's `endX` sentinel.
6. **Audio unlock chain** (`markAudioInteraction` ← every input path, incl. touch buttons). Adding a new input control that forgets `markAudioInteraction()` produces "silent game until some other key is pressed" — hard to notice in QA with a warm registry (`shorelineAudioUnlocked` persists across restarts).
7. **Scuttleclaw / stomp rules.** Self-contained and stable; lowest risk unless hitbox sizes or `isStomping*` thresholds are touched.

## 9. Recommended production sequence

Ordered, one focused pass each, per the production workflow doc's build-small doctrine. Do not combine.

**Code**
1. **Audio transcode + loading bar** (kills F-01's worst half; zero gameplay surface). WAV→OGG/M4A for the 21 audio entries in `AUDIO_PATHS`, plus a minimal `load.on('progress')` bar in `preload()`.
2. **Prod payload pass** (F-02): vendor `phaser.esm.min.js`, drop public sourcemaps — or commit to `vite build`. One decision, one pass.
3. **Retry flow decision** (F-04) — one-line auto-start or reworded prompt.
4. **Mobile restart affordance** (F-05) — touches the protected touch layer; needs its own QA round.
5. Defer: any split of ShorelineScene.ts. It is large but internally consistent and heavily commented; a refactor now risks every protected system at once for no player-visible gain.

**Runtime QA** (after passes 1-2, before any visual work)
6. Full desktop playthrough (all 5 levels + both bosses + creature room round-trip + all `?level=` routes), then a two-device mobile matrix (iOS Safari, Android Chrome): tap-start, hold-move, glide feel, switch cooldown, F-06 fullscreen, canal 12/12 walk-back, load time and memory.

**Visuals**
7. Nothing blocking public demo; heritage-steps reskin only if that level returns to campaign.

**Audio**
8. Loudness/consistency pass after the transcode (keep `dev_assets/audio_originals/` as masters).

**Trailer capture**
9. Optional `?capture=1` runtime gate replacing the compile-time constant (F-14); otherwise add "verify `TRAILER_CAPTURE_MODE === false`" to the pre-commit checklist.

**Commit/release discipline**
10. Branch-per-pass with PRs (this audit establishes the pattern); tag demo builds; decide LFS/history strategy for the tracked zips and `dev_assets/` (F-15); deploy `dist/` to a static host with brotli enabled.
